# PERMEAR — Configuration Reference

All user-editable configuration lives in `permear.yaml` at the root of your
`/config/` directory. Edit this file to customize PERMEAR for your setup.

More sections will be added in v9 (ARAS thresholds, memory parameters, cycle
schedules). For now, only the AI provider slots are configurable here.

---

## `providers` section

Defines the four AI provider slots PERMEAR uses. Each slot takes a Home
Assistant entity_id from a configured conversation or ai_task integration.

```yaml
providers:
  conversation: conversation.google_ai_conversation
  data: ai_task.deepseek_deepseek_v4_flash
  conversation_fallback: conversation.deepseek_deepseek_v4_flash
  data_fallback: ai_task.google_ai_task
```

### `conversation`

**Used for:** Telegram agent, voice (if wired). Interactive — requires
tools/function-calling support.

**Format:** `conversation.<integration_name>` — the entity_id of a configured
HA conversation integration.

**Examples:**
```yaml
conversation: conversation.google_ai_conversation     # Gemini (Google AI)
conversation: conversation.openai_conversation         # OpenAI or OpenRouter
conversation: conversation.anthropic_conversation      # Claude
conversation: conversation.deepseek_deepseek_v4_flash  # DeepSeek via HA integration
```

### `data`

**Used for:** all non-interactive cycle calls (Sleep Consolidation, Heartbeat
gray zone, Systems Consolidation, automation spec generation). Uses
`ai_task.generate_data` — does **not** require tools.

**Format:** `ai_task.<integration_name>` — the entity_id of a configured
HA AI Task integration.

**Examples:**
```yaml
data: ai_task.deepseek_deepseek_v4_flash    # DeepSeek (recommended: no daily quota)
data: ai_task.google_ai_task                # Gemini AI Task
data: ai_task.openai_ai_task               # OpenAI
```

### `conversation_fallback`

**Used for:** takes over the conversation slot if the primary fails 3 consecutive
times. **Must also support tools** — otherwise PERMEAR returns an honest error
to the user (no degraded mode). If set to the same value as `conversation`,
it behaves as a retry.

### `data_fallback`

**Used for:** takes over the data slot if the primary fails. No tools required.
If set to the same value as `data`, it behaves as a retry.

---

## Reading B — the honesty contract

If both `conversation` and `conversation_fallback` fail, PERMEAR tells the
user: "Sistema temporariamente indisponível. Tente em alguns minutos."

It does **not** send a response pretending to be a different system, or fall
back to a rule-based mode while claiming to be the AI agent. This is a design
decision, not a limitation.

---

## Changing providers

`permear.yaml` is the single source of truth. Edit it and reload HA:

```yaml
providers:
  data: ai_task.google_ai_task
```

Then: Dev Tools → YAML → Reload All (or restart HA).

The YAML automations read providers via `sensor.permear_config` (a command_line
sensor that reads `permear.yaml` at startup and every hour). No dual-maintenance
needed — `secrets.yaml` no longer stores provider values.

## `memory/guidelines.json`

Not in `permear.yaml`, but this is the other user-editable file. It contains:

- `residents`: list of household members. The primary resident (index 0) is
  used for context in ARAS gray-zone prompts.
- `action_items`: weekly suggestions and pending items generated by Systems
  Consolidation. Editable manually.

```json
{
  "residents": [
    {
      "name": "YourName",
      "role": "primary",
      "entity": "person.your_name"
    }
  ],
  "action_items": {
    "padroes": [],
    "pendencias": [],
    "sugestoes": []
  }
}
```
